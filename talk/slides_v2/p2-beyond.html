Direction: Finding 2. Speed is a line; most of a speed edit is the same at every frame, so a pooled edit shifts the trajectory rather than making the disk faster. Acceleration, honestly: every accelerating clip starts at rest, so acceleration and mean speed are one variable here; a decorrelated render is in flight. Position is a plane. Frame count: the code advances one step per frame at every speed, 0.99 to 1.00, and with the disk standing still it still advances 0.55 to 1.07 of the moving rate, the untrained copy 1.02 to 1.10; static clips sit 2.3 to 2.9 times farther from moving ones. So it is a positional frame index that training rescales, not an odometer; with the slots deranged it follows the slot (p5_time_shuffle.json). It is steerable inside the encoder, within 0.1 steps, but a +2-step edit advances the forecast −0.21 of the real displacement against 1.15 for real later frames.
