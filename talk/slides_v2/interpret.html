What the results say

Training builds a per-patch code

A pooled probe reads the disk from any network. What V-JEPA 2 adds is a direction code at every patch that becomes one frame-wide code in the emergence zone.

Each variable has its own shape

Direction is a ring, speed a line, the two together a cone, and elapsed time a clock. The shape decides whether a straight edit stays among real states.

An edit counts only when the forecast follows

Mid-depth edits are erased within four blocks by attention and MLP alike. Late edits reach the predictor, and there the spline's path is what the forecast tracks.

The code leaves the object before the predictor reads it

Through block 12 the forecast reads direction from the disk's own tokens. By block 22 it reads it from the whole frame, which is where a pooled edit lands.

Interpretation

~70 s. Four claims I would defend, each with the number behind it. The fourth is the one the paper's authors asked for in their future work: swapping clip B's disk tokens into clip A at block 12 moves the predictor's direction forecast 88 percent of the way to B, swapping the background moves it 12 percent; at block 22 the disk tokens move it 22 percent and the background 77 percent, close to the token shares of 13 and 87 percent, so the code is object-bound through the emergence zone and frame-wide where the predictor reads it. Position-matched pairs give the same curve, so it is not the disk's location. File p5_token_patching.json. One: the per-patch code is training-selective; V-JEPA 2's mean per-patch R squared is 0.96 at block 6 while a random network's never passes 0.39, and on a harder render the half-frame jump appears at the paper's depth on all three seeds. The reading: the emergence zone is not where direction first becomes decodable, it is where the code stops depending on where the disk is. Two: geometry. Direction centroids form a ring, label-free angle correlation minus 0.98; speed and acceleration are straight to within a quarter of the centroid noise; the velocity sheet is a cone whose ring radius grows with speed; and elapsed time advances one coordinate per step at every speed. The consequence for steering: on a ring the chord crosses the hollow centre and its readout radius collapses to 0.23, on lines the spline adds nothing, and on the sheet one factored edit sets both variables. Three: use. Per-patch readability peaks at block 14, but edits at blocks 2, 8 and 12 are undone within four blocks, attention and MLP removing 45 and 40 percent of the edit, and only block-22 edits move the forecast, 11.3 degrees from the target against 92.1 unedited. The reading: the depth to intervene at is set by what the predictor consumes, not by where a probe reads best, and along the block-22 path the forecast follows the spline through the intermediate directions while the chord's forecast jumps. One I would not defend: that any of this transfers to Kubric-scale scenes without checkpoint experiments and more than one harder render.
